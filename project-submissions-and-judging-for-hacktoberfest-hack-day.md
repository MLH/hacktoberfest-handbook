# Project Submissions and Judging for Hacktoberfest Hack Day

This page applies to approved `Hacktoberfest Hack Day` events. OrganizerHQ Challenges is mandatory for every Hacktoberfest Hack Day event and cannot be substituted by an alternative submission workflow.

Work on submitted projects may not begin before the Fest. Every submitted project must be created during the one-day event.

## Participant Submission Process

Participants must register for the event through OrganizerHQ and check in before submitting a project. On the event’s OrganizerHQ page, they will see a button that opens the available challenges.

<figure><img src=".gitbook/assets/image.png" alt=""><figcaption></figcaption></figure>

Participants should be prepared to provide:

* A link to the project (open-source challenges require a public GitHub repository)
* Project name and description
* Demo URL, if available
* Technologies and models used
* Every challenge the team is entering

The submission form does not include a separate license-attestation field, so participants should make the project's open-source license clear in the repository.

See [Open-Source Prize Categories](fest-planning-guide/open-source-prize-categories.md) for the organizer-selectable challenge definitions. Selected Hacktoberfest Hack Day events may also receive an assigned [Hack Days partner prize category](fest-planning-guide/hack-days-partner-prize-categories.md).

## Exporting Submissions

All submitted projects can be viewed by the organizer in OrganizerHQ. Open **Registrations**, then select **Export Challenge Submissions**.

![](<.gitbook/assets/image (1).png>)

Use the exported submission list for eligibility review and judging.

## Judging

Judge every project against the applicable challenge definition and submission requirements. A strong judging process should:

{% stepper %}
{% step %}
## <sub>Give every eligible submission the same opportunity to be reviewed.</sub>
{% endstep %}

{% step %}
## <sub>Prioritize usefulness, originality, implementation quality, and fit with the challenge.</sub>
{% endstep %}

{% step %}
## <sub>Confirm the repository, license, model, harness, or partner-technology requirements before selecting a winner.</sub>
{% endstep %}

{% step %}
## <sub>Record enough reasoning to explain the decision to participants and report the result to the MLH Hacktoberfest team.</sub>
{% endstep %}
{% endstepper %}

Each chosen open-source challenge has one winning team. Every member of that team receives a DEV Badge on their DEV account. Hack Days partner prize categories use the prize and judging instructions in their assigned module (see Hack Days Partner Modules tab).

A reminder that Hacktoberfest does not use pull-request counts as the basis for these prizes.
